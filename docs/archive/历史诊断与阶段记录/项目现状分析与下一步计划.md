### 计划 A: 完善 UI 到真实数据流集成 (推荐)

**目标**: 让 UI 显示真实的游戏画面和状态数据

#### 阶段 1: 实现 EngineThread (6h)
```python
# ui/threads/engine_thread.py
class EngineThread(QThread):
    """核心引擎工作线程"""

    frame_ready = pyqtSignal(np.ndarray)  # 30 FPS
    status_update = pyqtSignal(dict)       # 5 Hz
    log_message = pyqtSignal(str, str)
    error_occurred = pyqtSignal(str)

    def __init__(self, config):
        super().__init__()
        self.config = config

    def run(self):
        # 初始化核心引擎
        capture_engine = CaptureEngine(config)
        detector = create_detector(config)
        world_model = WorldModel()
        fsm = BotFSM()
        input_driver = InputDriver()

        # 主循环
        while self.running:
            frame = capture_engine.get_frame()
            detections = detector.detect(frame)
            context = world_model.update(detections)
            command = fsm.update(context)
            input_driver.execute(command)

            # 发送信号
            self.frame_ready.emit(frame)
            self.status_update.emit(...)
```

**验收标准**:

- ✅ 实时画面显示（FPS ≥ 25）

### 5.1 技术债务

| 债务项 | 严重程度 | 预计修复时间 | 说明 |
|---------|----------|--------------|------|
| **WorldModel 未集成** | 高 | 2h | 代码已实现，但主流程未调用 |

| **日志过于详细** | 低 | 1h | DEBUG 级别日志过多，影响性能 |

### 5.2 性能优化建议

| 优化项 | 预期收益 | 实现难度 |
|---------|-----------|----------|
| **FP16 推理** | FPS 提升 50% | 中（将模型转换为 FP16） |
| **输入分辨率降低** | FPS 提升 100% | 低（1920→640×416，但检测精度下降） |
| **TensorRT 加速** | FPS 提升 200% | 高（需要将模型转换为 TensorRT 格式） |
| **多线程分离** | FPS 提升 30% | 中（推理线程和逻辑线程分离） |
| **减少日志输出** | 延迟降低 10ms | 低（调整日志级别） |

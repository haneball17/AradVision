### 1.3 定义

* **ROI (Region of Interest)** ：感兴趣区域，指屏幕中包含游戏画面的特定矩形区域。
* **Y轴对齐 (Y-Axis Alignment)** ：DNF作为2.5D游戏特有的攻击机制，指玩家必须与怪物处于同一水平线（深度）才能有效命中。
* **置信度 (Confidence)** ：目标检测模型判断某个对象是特定类别的概率值（0.0-1.0）。
* **FSM (Finite State Machine)** ：有限状态机，用于控制角色的行为流转（如：待机 -> 索敌 -> 攻击）。

## 2. 任务概述

### 2.1 目标

开发一套基于计算机视觉（Computer Vision）的外部辅助系统，在不读取游戏内存、不注入代码的前提下，通过识别屏幕图像模拟玩家操作，实现特定副本（如“洛兰”）的自动化通关。

### 2.2 用户特点

用户具备 Python 编程基础及 DNF 游戏机制知识，能够理解命令行输出及调试窗口的视觉反馈，并具备自行调整配置文件（Config.yaml）的能力。

### 2.3 假定与约束

* **分辨率约束** ：游戏客户端需运行在 800x600 或 1067x600 窗口模式下。
* **输入约束** ：系统通过模拟底层键盘信号（DirectInput）与游戏交互。
* **硬件约束** ：系统需在配备 NVIDIA GTX 1060 或以上显卡的设备上运行，以保证推理速度。
* **合规性约束** ：仅限单机/私服环境下的技术研究，严禁用于官方服务器破坏游戏平衡。

## 3. 需求规定

### 3.1 对功能的规定

本系统主要划分为三个核心子系统： **视觉感知子系统** 、 **决策逻辑子系统** 、 **执行控制子系统** 。

#### 3.1.1 视觉感知子系统 (Vision Subsystem)

**FUNC-01: 屏幕实时捕获**

* **输入** ：操作系统显示的桌面画面。
* **处理** ：定位游戏窗口句柄，实时截取游戏区域图像。
* **输出** ：BGR 格式的图像帧（Frame）。
* **要求** ：捕获帧率需 >= 30 FPS。

**FUNC-02: 动态对象检测 (Object Detection)**

* **输入** ：单帧游戏图像。
* **处理** ：使用 YOLOv8 模型进行推理。
* **输出** ：对象列表，包含类别（Monster, Boss, Item, Gate）、坐标框 (x, y, w, h) 及置信度。
* **精度要求** ：在光照正常情况下，对怪物识别准确率（mAP）需 > 80%。

**FUNC-03: 静态UI与状态识别**

* **输入** ：单帧游戏图像。
* **处理** ：

1. **自身状态** ：通过颜色阈值分析血条（HP）和蓝条（MP）区域。
2. **技能冷却** ：检测技能栏特定图标是否变灰或存在倒计时。
3. **小地图定位** ：识别小地图中的白色箭头（自身）和牛头图标（BOSS房）。

* **输出** ：HP百分比、可用技能列表、房间相对位置。

#### 3.1.2 决策逻辑子系统 (Logic Subsystem)

**FUNC-04: 坐标空间映射**

* **描述** ：将视觉识别到的像素坐标 **$(x, y)$** 转换为游戏内的逻辑坐标。
* **逻辑** ：需通过对象底部的阴影中心点来确定其实际落地位置（Ground Truth Position），以修正2.5D视角带来的视觉误差。

**FUNC-05: 战斗策略 (Combat Logic)**

* **输入** ：怪物列表、自身位置。
* **处理** ：

1. **索敌** ：选择距离最近的怪物作为目标。
2. **Y轴对齐** ：优先控制角色移动至与目标相同的 Y 轴（允许 ±10 像素误差）。
3. **X轴逼近** ：在 Y 轴对齐的前提下，缩短 X 轴距离至攻击范围。
4. **攻击释放** ：根据怪物类型选择普攻或技能连招。

* **输出** ：移动方向向量、攻击指令。

**FUNC-06: 房间导航 (Room Navigation)**

* **描述** ：当房间内无怪物时，系统应能寻找通往下一房间的“门”或“传送阵”。
* **逻辑** ：

1. 识别场景中的 Gate 对象。
2. 判断 Gate 是否处于开启状态。
3. 规划移动路径避开障碍物（如石头、树桩）。

#### 3.1.3 执行控制子系统 (Action Subsystem)

**FUNC-07: 拟人化输入模拟**

* **输入** ：逻辑层发出的抽象指令（如 `Move_Left`, `Attack`）。
* **处理** ：将指令转换为 DirectX 扫描码（Scan Code），并调用 `pydirectinput` 或 Win32 API 发送。
* **特性** ：

1. 支持按键保持（Hold）以实现跑动。
2. 支持双击（Double Tap）以实现冲刺。
3. 加入微小的随机延迟（50ms-150ms）以模拟人类操作。

**FUNC-08: 紧急熔断机制**

* **描述** ：任何时候按下特定热键（如 F12），系统必须立即停止所有输入并挂起逻辑。

### 3.2 对性能的规定

* **实时性** ：从屏幕画面变化到系统发出按键响应的端到端延迟（Latency）应小于 150ms。
* **推理速度** ：YOLO 模型在 GPU 加速下，单帧推理耗时应小于 30ms。
* **资源占用** ：CPU 占用率不超过 40%（保留资源给游戏本体），显存占用不超过 2GB。

### 3.3 输入输出要求

* **配置文件** ：系统需支持 YAML 格式配置文件，允许用户修改置信度阈值、按键映射表和模型路径。
* **日志输出** ：系统需在控制台输出运行日志（Info/Error），并支持将错误日志写入文件。
* **可视化调试** ：系统需提供一个 Debug 窗口，在原始画面上绘制识别框、目标连线和状态机当前状态文本。

### 3.4 数据管理能力要求

* **数据集存储** ：原始截图和标注文件（XML/TXT）需按文件夹分类存储。
* **模型版本管理** ：不同迭代周期的模型权重文件需保留版本号（如 `yolov8n_dnf_v1.pt`）。

### 3.5 故障处理要求

* **目标丢失** ：当连续 5 帧未检测到任何目标时，角色应进入“巡逻/发呆”状态，而不是一直按着方向键撞墙。
* **卡死检测** ：如果角色坐标在 5 秒内无变化且处于移动状态，系统应判定为卡死，并尝试随机移动或使用“后跳”脱困。

## 4. 运行环境规定

### 4.1 设备

* **处理器** ：Intel Core i5-8400 或同级以上。
* **内存** ：16GB DDR4。
* **显卡** ：支持 CUDA 11.x 的 NVIDIA 显卡。

### 4.2 支持软件

* **操作系统** ：Windows 10/11 64-bit。
* **编程语言** ：Python 3.10。
* **依赖库** ：见 requirements.txt (PyTorch, Ultralytics, OpenCV, MSS)。

### 4.3 接口

* **输入接口** ：USB 键盘鼠标（系统需接管其信号）。
* **显示接口** ：标准显示器输出（1080p）。

# 测试运行指南

## 1. 环境准备

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

如果只验证 UI，可额外确认：

```bash
pip install PyQt5
```

## 2. 推荐验证顺序

### 2.1 语法与导入检查

```bash
python3 -m compileall core input logic vision ui tests main.py scripts
```

### 2.2 单元测试

```bash
python3 -m pytest -q
```

如果只关注当前主线，优先执行：

```bash
python3 -m pytest -q \
  tests/test_config_capture_backend.py \
  tests/test_capture_factory.py \
  tests/test_config_dungeon_run.py \
  tests/test_dungeon_run_pipeline.py \
  tests/test_world_model.py
```

### 2.3 集成测试

```bash
python3 -m pytest -q tests/integration/test_full_flow_mock.py
```

该用例用于验证 mock 环境下的主流程装配与基本运行闭环。

## 3. UI 验证

### 控制面板冒烟

```bash
python3 scripts/test_pyqt_ui.py
```

### 详细交互检查

参考 [PyQt5-UI测试指南](PyQt5-UI测试指南.md)。

### 时间线工作台

```bash
python3 scripts/test_timeline_ui.py
```

时间线工作台属于辅助工具，不是默认主线入口；验证失败不会阻断固定路线 MVP 主链路。

## 4. 捕获后端验证

Windows 下需要验证 WGC 时，建议额外执行：

```bash
python3 scripts/verify_capture_backend.py --config configs/config.yaml
```

若需要排查 WGC 失败后的自动降级行为，可结合 `capture.backend` 与 `capture.allow_fallback` 配置分别验证。

## 5. 真实环境验证注意事项

- 真实输入前，确认 `configs/config.yaml` 中 `input.type`、`capture.use_mock` 与 `capture.backend` 设置符合预期。
- 保持 `F12` 紧急停止可用。
- 优先先跑 Mock，再切真实捕获，再切真实输入，避免一次性打开全部风险面。

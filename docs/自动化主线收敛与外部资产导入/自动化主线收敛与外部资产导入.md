# 自动化主线收敛与外部资产导入

## 背景

项目曾并行推进两条路线：

1. 自动化运行主链路
2. 训练数据资产管理工作台

当前决策是暂停第二条路线，把主仓重新聚焦到自动化运行和真实感知接入。

## 已执行的仓库策略

- 归档分支：`docs/workbench-v2-refactor`
- 归档标签：`archive/workbench-v2-freeze-2026-03`
- 当前主线开发分支：`feat/runtime-refocus-and-external-assets`
- 后续集成线：`dev`
- 稳定线：`main`

约束规则：

- 不再把工作台分支合并回 `dev` 或 `main`
- 如果未来重新评估工作台，只能从归档点重新开分支

## 当前主线范围

### 保留

- `CaptureEngine`
- `Detector` 接口与 Mock 实现
- `WorldModel`
- `BotFSM` / `CombatLogic` / `PathPlanner`
- `InputDriver` / `KillSwitch`
- 经典 `PyQt5` 控制面板

### 暂停

- 时间线工作台
- 仓库内采集/筛选/预标注桌面流程
- 工作台专题设计与 UI 迭代

## 外部资产导入约定

### 原则

- 原始视频采集发生在仓库外
- 仓库内只保留导入规范，不维护采集 UI 或筛选 UI
- 如果需要仓库内临时落地，只能使用 gitignore 目录

### 本地暂存目录

以下目录只用于本地暂存，不进入版本控制：

- `assets/videos/`
- `assets/imported/`
- `assets/frames/`

### 会话命名

统一使用：

```text
YYYYMMDD_<主题或地图>_<来源标识>
```

示例：

```text
20260312_loran_obs
20260312_boss_route_capturecard
```

### 导入结果结构

```text
assets/imported/<session_id>/
├── images/
└── manifest.json
```

`manifest.json` 最小字段：

- `session_id`
- `source_video`
- `capture_time`
- `fps`
- `resolution`
- `scene_hint`
- `game_build_or_region`
- `notes`

## 推荐工作流程

1. 使用外部录屏工具或你自己的截流方案录制视频
2. 将原始视频保存在仓库外资产目录
3. 在仓库外做抽帧、去重、粗筛
4. 把筛选后的图片和 `manifest.json` 放入约定目录
5. 进入标注与训练流程
6. 将训练好的模型本地放入 `models/` 并更新配置

## 当前不做的事

- 不新增工作台替代 UI
- 不新增仓库内时间线脚本
- 不把抽帧/筛选重新做成桌面产品

这份文档的目标是划清边界，而不是重建另一套数据平台。

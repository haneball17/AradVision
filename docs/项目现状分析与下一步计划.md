# AradVision 项目现状分析与下一步计划

**分析日期**: 2026-03-12
**当前主线**: 自动化运行链路 + 外部资产导入规范

## 一、当前状态

### 已明确的主线

- 主程序仍围绕 `Capture -> Detect -> WorldModel -> FSM -> Input` 运行链路推进。
- Mock 检测、世界模型、状态机、输入执行和捕获工厂已经具备继续演进的基础。
- 经典 `PyQt5` 控制面板保留，但仅作为辅助监控和调试界面。

### 已暂停的方向

- 训练数据资产管理工作台
- 仓库内时间线采集/筛选/预标注流程
- 为工作台服务的专题 UI 迭代

这些内容不再是当前交付目标，相关实现已归档到工作台历史分支。

## 二、完成度判断

| 方向 | 状态 |
|------|------|
| 数据模型、输入层 | 已有稳定基础 |
| 决策层 | 主体可用，仍需针对真实场景继续补强 |
| 感知层 | Mock 完整，真实 YOLO 仍待接入 |
| 基础设施层 | 配置、日志、捕获链路可继续迭代 |
| 经典 UI | 可保留，但不作为主战场 |
| 训练数据工作台 | 暂停，不继续推进 |

## 三、当前问题

1. 项目历史文档仍混合了“自动化主链路”和“训练数据工作台”两条叙事。
2. 真实 YOLO 检测器和模型资产仍未进入主链路。
3. 训练数据获取方式已经改变，但仓库规范尚未完全同步。
4. 部分旧文档仍默认仓库内会承担采集与筛选流程。

## 四、下一步

### P0

- 保持主链路聚焦，避免重新引入工作台范围
- 明确外部视频流采集、抽帧和导入边界
- 推进真实检测器接入计划

### P1

- 继续完善主循环、UI 线程和真实输入的稳定性
- 补充针对当前主线的测试与验证脚本
- 更新说明文档，减少历史方案干扰

### P2

- 等真实检测与训练流程稳定后，再评估是否需要新的轻量数据工具
- 若未来恢复工作台方向，必须基于归档分支重新评审，而不是直接回滚主线

## 五、结论

当前最合理的推进方式不是继续做仓库内数据工作台，而是把精力集中到：

1. 自动化运行链路稳定化
2. 真实感知链路接入
3. 外部资产导入规范与训练闭环

这条路径更符合当前决策，也能显著减少主线叙事与代码结构的分散。

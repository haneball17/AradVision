## 1. 需求审核（Code Prompt Coach）
1. 清晰性：目标明确，核心是“按时间线浏览并按区间抽样导出”。
2. 具体性：已给出关键功能（任意时间区间、采样频率）。
3. 上下文：与现有 PyQt5 UI、`samples.jsonl` 元数据体系可直接衔接。
4. 结构化补充（本方案默认）：首版以桌面端单窗口工具为主，不引入新前端框架。

## 2. 设计目标
1. 30 秒内完成一次“区间选择 + 频率抽样 + 导出”。
2. 对错误操作有明显防呆（区间无效、导出量过大、磁盘空间不足）。
3. 与现有主题、日志、配置机制保持一致，开发成本可控。
4. 支持 1 万张级别样本浏览，主线程不阻塞。
5. 提供采集控制入口，首版支持直接“开始/停止”采集。
6. 统一单 UI 入口，支持“采集工作区 + 预标注工作区”切换，无需启动两个独立应用。

## 3. 信息架构
1. 顶部：工作区切换条（`采集工作区` / `预标注工作区`）。
2. 采集工作区：左侧会话筛选，中部时间线与缩略图，右侧导出参数。
3. 预标注工作区：左侧任务与数据源，中部结果预览，右侧任务参数与启动控制。
4. 顶部次级控制：采集控制条（开始/停止，P1 增加暂停/继续）。
5. 底部：统一日志与状态栏。

## 6. 功能清单
### 6.1 必须功能（P0）
1. 工作区切换入口：单 UI 内切换 `采集工作区` 与 `预标注工作区`。
2. 采集控制入口：提供“开始/停止”按钮，直接拉起/停止采集脚本。
3. 采集状态展示：`空闲/采集中/停止中/异常`。
4. 时间线双锚点选择（A/B）。
5. 区间采样频率（1s、2s、5s、自定义）。
6. 导出预估数量与分布统计。
7. 导出结果与 `selection_manifest.json`。
8. 预标注任务入口：选择数据集/模型/版本并触发开始与停止。
9. 预标注任务状态：展示 `排队/运行中/完成/失败` 与进度百分比。
10. 预标注结果定位：任务完成后一键打开输出目录与版本 manifest。

### 6.2 增强功能（P1）
1. 质量过滤：`blur_score`、`similarity_to_prev`。
2. 场景筛选：`combat/navigate/loot/boss/other`。
3. 快捷键：`[` 设A，`]` 设B，`Ctrl+E` 导出。
4. 采集暂停/继续：在同一会话内暂停落盘并可继续，保持编号连续。
5. 预标注参数模板：按模型版本保存/加载阈值模板。
6. 失败任务重试：支持“仅重跑失败样本”。
7. 预标注结果叠加预览：显示框、类别、置信度并支持快速定位错误样本。

### 6.3 进阶功能（P2）
1. 区间批量修正场景标签。
2. 导出前后分布对比报告。
3. 预标注复核入口：对接外部标注工具（CVAT/LabelImg）进行人工复核流转。

### 6.4 采集控制分级决策（新增）
1. `开始/停止` 归入 P0：直接决定是否能在 UI 内闭环完成“采集 -> 筛选 -> 导出”。
2. `暂停/继续` 归入 P1：有价值但非首版必需，避免 P0 过早引入状态机复杂度。
3. 暂停语义：停止新增落盘，不结束会话。
4. 继续语义：在同一会话续写，编号连续。
5. 停止语义：执行会话收尾并写入最终统计。

### 6.5 预标注入口分级决策（新增）
1. `开始/停止` 归入 P0：确保不需要第二个 UI 即可触发预标注流程。
2. 参数模板与失败重试归入 P1：提升效率但不阻塞首版可用性。
3. UI 内复核与编辑归入 P2：保持首版范围收敛，避免与专业标注工具重叠。

## 7. 技术实现建议（贴合现有项目）
1. UI 框架：复用 PyQt5（不新增 Web 依赖）。
2. 新增模块建议：
- `ui/widgets/workspace_switch_bar.py`：工作区切换条。
- `ui/widgets/timeline_panel.py`：时间线轨道与缩放逻辑。
- `ui/widgets/frame_strip.py`：缩略图时间流。
- `ui/widgets/export_panel.py`：区间/频率/过滤/导出。
- `ui/widgets/capture_control_bar.py`：采集控制条（开始/停止，P1 扩展暂停/继续）。
- `ui/widgets/pseudo_label_panel.py`：预标注任务参数、任务状态、结果入口。
- `ui/timeline_window.py`：工作台主窗口。
3. 主窗口结构建议：`QTabWidget` 或 `QStackedWidget` + 顶部切换条，统一承载两个工作区。
4. 数据源：优先读取 `meta/samples.jsonl`，无元数据时回退文件名时间戳。
5. 输出规范：`assets/images/selected/<session>/<export_id>/`。
6. 进程控制建议：
- 采集：首选拉起 `scripts/collect_yolo_data.py`，兼容 `scripts/capture_training_data.py`。
- 预标注：拉起 `scripts/generate_pseudo_labels.py` 或等效脚本，UI 仅负责参数组装、进度展示、失败回收。
- 统一通过子进程管理器封装：启动、停止、超时、日志流、退出码解释。

## 8. 验收标准
1. 1000 张样本加载时间 < 2 秒，滚动与拖拽无明显卡顿。
2. 5000 张样本加载时间 < 4 秒，时间线缩放无明显掉帧。
3. 10000 张样本首次可见区域渲染 < 2 秒，完整缩略图采用懒加载。
4. 任意 A/B 区间导出结果与预估误差为 0。
5. 导出吞吐不低于 100 张/秒（copy 模式，1080p jpg，SSD 环境）。
6. 导出清单包含参数、时间范围、过滤条件、样本数量。
7. 无效区间、异常路径、磁盘不足有明确错误提示。
8. 点击“开始”后 3 秒内进入采集中状态，点击“停止”后 5 秒内完成停采并写入会话收尾信息。
9. P1 场景下暂停后不再新增样本，继续后样本编号连续且写入同一会话。
10. 工作区切换无需重启应用，切换耗时 < 300ms（不触发主线程卡顿）。
11. 预标注任务点击“开始”后 3 秒内进入运行状态，点击“停止”后 5 秒内完成停止态收敛。
12. 预标注任务完成后可直接定位到输出目录与 manifest，失败任务可读取错误摘要。

## 10. 时间语义（新增）
1. 区间定义为闭区间 `[A, B]`，包含 A 与 B 对应样本。
2. 若用户输入 `A > B`，系统自动交换并提示。
3. 存储基准统一使用 `timestamp_ms`（UTC 毫秒）；`timestamp_iso` 仅用于展示与日志。
4. UI 显示默认使用系统本地时区，鼠标悬停同时显示 UTC。
5. 时间戳解析优先级：
- `timestamp_ms`
- `timestamp_iso`
- 文件名时间戳
- 文件 `mtime`

设计理由：用单一数值时间轴做计算，避免时区与字符串解析差异导致的不确定行为。

## 11. 抽样算法（新增）
1. 采用“时间网格 + 最近帧匹配”模式。
2. 计算网格点：`t_k = A + k * interval_ms`，直到 `t_k > B`。
3. 在窗口 `[-tolerance_ms, +tolerance_ms]` 内选择离 `t_k` 最近且未使用样本。
4. 默认 `tolerance_ms = min(0.4 * interval_ms, 200)`。
5. 若窗口内无样本，按 `missing_policy=skip` 跳过并累计 `missing_count`。
6. 导出结束后在 manifest 输出：`grid_count/selected_count/missing_count/duplicate_drop_count`。

设计理由：比严格命中更稳健，比简单最近邻更可控，且结果可复现。

## 12. 导出策略（新增）
1. 导出模式：默认 `copy`，可选 `hardlink`（仅同盘且系统支持时）。
2. 命名规则：导出文件统一顺序命名（`000001.jpg`），源路径映射写入 manifest。
3. 冲突策略：默认 `new_dir`（自动追加 `export_id`），可选 `error/overwrite`。
4. 重名处理：同次导出由顺序命名规避，不依赖原文件名去重。
5. 输出目录约定：`assets/images/selected/<session>/<export_id>/`。

设计理由：默认策略以安全性优先，避免误覆盖；高级策略按需开启。

## 13. 性能策略（新增）
1. 元数据与图像解码分离：主线程仅加载元数据，缩略图在后台线程解码。
2. 缩略图懒加载：仅渲染可视区与预加载窗口。
3. 预加载窗口：当前可视区前后各 200 张，可配置。
4. 缩略图缓存上限：默认 800 张，采用 LRU 逐出。
5. 时间线绘制降采样：单次渲染最多 2000 个点，超出部分聚合显示。
6. 并发解码线程：`min(4, CPU核心数-1)`，避免争抢 UI 线程。
7. 统计计算分批执行：每批 500 条，批间让出事件循环。

设计理由：控制主线程负载和内存峰值，保证 1 万张级别下可操作性。

## 14. 失败与回滚（新增）
1. 导出事务模型：先写入临时目录 `.tmp_export_<id>`，成功后原子重命名为正式目录。
2. 用户取消导出：停止后清理临时目录，并在日志记录已处理数量。
3. 磁盘不足：立即中止，保留 `errors.jsonl` 与失败原因，不生成正式导出目录。
4. 坏图像或读写异常：按 `on_error=skip` 跳过并记录，不中断整批导出。
5. 崩溃恢复：下次启动扫描残留临时目录，支持“清理/恢复”二选一。
6. 可选调试开关：`keep_failed_temp=true` 时保留临时目录用于排障。

设计理由：保证结果一致性，降低半成品污染风险，并保留足够排障线索。

## 15. 文档边界说明（新增）
1. 本文档覆盖 UI 工作台能力：采集控制、时间线浏览、区间筛选、抽样导出、预标注任务入口、导出错误恢复。
2. 本文档对预标注仅定义“任务编排与状态展示”，不重复定义模型算法细节。
3. 训练工程能力（数据集划分、防泄露、YOLO 格式校验、伪标签版本管理、尺寸分析）统一在：
- `docs/YOLO训练数据采集与伪标签方案/YOLO训练数据采集与伪标签方案.md`
4. UI 作为训练工程入口时，仅保留参数收集、任务触发、进度反馈、结果定位，不承担训练策略决策。

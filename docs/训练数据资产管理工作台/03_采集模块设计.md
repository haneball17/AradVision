# 训练数据资产管理工作台：采集模块设计

**版本**：v2.2  
**日期**：2026-02-26  
**角色**：架构与逻辑工程师（yangmq17）

## 1. 模块职责
采集模块负责：
1. 目标窗口选择与捕获引擎启动（WGC 优先，MSS 兜底）。  
2. 帧采样调度与图片落盘。  
3. 自动质量过滤（模糊、重复、异常帧）。  
4. 写入会话级与样本级元数据。

采集模块不负责：
1. 人工筛选与标记。  
2. 预标注推理。  
3. 训练集拆分与导出。

## 2. 核心组件
1. `WindowDiscoveryService`：枚举可选窗口，返回窗口标题与句柄。  
2. `CaptureOrchestrator`：采集生命周期控制（start/pause/resume/stop）。  
3. `SamplingScheduler`：按固定频率触发采样。  
4. `QualityFilter`：执行 blur/duplicate/basic-integrity 过滤。  
5. `SessionWriter`：写 `session_manifest.json` 与 `samples.jsonl`。

## 3. 启停流程
```text
选择窗口 -> 校验窗口可见性 -> 创建会话目录 -> 启动后端 -> 周期取帧 -> 过滤 -> 落盘 -> 写样本记录
```

停止流程：
1. 停止调度器。  
2. 刷新缓冲写入。  
3. 汇总统计写回 `session_manifest.json`。  
4. 关闭捕获资源与句柄。

## 4. 配置契约（config.yaml）
```yaml
capture:
  backend: auto            # auto|wgc|mss
  window_title: DNF Taiwan
  fps_target: 20
  save_format: jpg
  jpeg_quality: 92
  output_root: assets/images/raw
  auto_activate: false
  check_focus: true

quality:
  blur_enabled: true
  blur_threshold_mode: dynamic   # dynamic|fixed
  blur_threshold_fixed: 80.0
  duplicate_enabled: true
  duplicate_metric: mse
  duplicate_threshold: 3.0
```

## 5. 时间语义与时间戳优先级
时间戳字段统一使用 UTC 毫秒 `timestamp_ms`。  
解析优先级：
1. 采集时系统时间（主来源）。  
2. 如需回放修复，使用样本元数据时间。  
3. 文件名时间仅作兜底，不作为权威时间。

## 6. 抽样算法
默认按固定采样间隔（`1/fps_target`）触发。  
若取帧波动，采用“触发即取最近可用帧”策略，记录实际间隔：
1. `expected_interval_ms`  
2. `actual_interval_ms`

丢帧策略：
1. 连续丢帧 <= 3：告警并继续。  
2. 连续丢帧 > 3：标记后端异常并尝试软重连。  
3. 重连失败：结束会话并输出错误摘要。

## 7. 质量过滤策略
1. 模糊过滤：拉普拉斯方差或等价指标。  
2. 重复过滤：与上一有效帧做 MSE（可扩展 SSIM）。  
3. 异常过滤：空帧、尺寸异常、编码失败。

动态阈值建议：
1. 会话启动后先采样 20 帧建立基线。  
2. `blur_threshold = baseline * 0.3`（可配置）。

## 8. 文件命名与路径安全
1. 会话目录：`ui_capture_{YYYYmmdd_HHMMSS}_{safe_window_title}`  
2. 样本文件：`frame_{index:06d}.jpg`  
3. 窗口标题需做路径清洗：移除非法字符并截断长度。  
4. 为防 Windows 长路径问题，目录名总长度限制在 80 字符内。

## 9. 元数据契约
### 9.1 `session_manifest.json`
```json
{
  "schema_version": "v2.2",
  "session_id": "ui_capture_20260226_120000_dnf_taiwan",
  "created_at": "2026-02-26T12:00:00Z",
  "backend": "wgc",
  "window": {"title": "DNF Taiwan", "handle": 123456},
  "resolution": {"width": 1920, "height": 1080},
  "sampling": {"fps_target": 20, "expected_interval_ms": 50},
  "quality": {"blur_mode": "dynamic", "blur_threshold": 78.2, "dup_threshold": 3.0},
  "stats": {"captured": 2400, "saved": 1820, "filtered_blur": 320, "filtered_dup": 260}
}
```

### 9.2 `samples.jsonl`（每行一个样本）
```json
{
  "sample_id": "ui_capture_.../frame_000123.jpg",
  "timestamp_ms": 1772088000123,
  "scene": "combat",
  "state": "raw",
  "image_path": "images/frame_000123.jpg",
  "width": 1920,
  "height": 1080,
  "backend": "wgc",
  "window_state": "foreground",
  "quality": {"blur_score": 95.4, "dup_mse_to_prev": 1.7},
  "manual_flag": "none",
  "filtered": false,
  "filter_reason": ""
}
```
约束：采集阶段必须写入 `manual_flag=none`，后续由筛选模块更新为 `star/reject/review`。

## 10. 异常与恢复
1. 图片写入失败：记录错误并跳过，累计阈值超过上限则中止会话。  
2. 磁盘不足：停止采集，写失败摘要并提示剩余空间。  
3. 后端异常：自动降级或停止并提示用户重试。  
4. 会话结束时必须保证 manifest 可读，避免“脏会话”。

## 11. 日志与监控
关键日志：
1. 后端选择与降级原因。  
2. 每 N 帧统计：`frames/fps/latency/filtered_rate`。  
3. 错误分类：capture_fail/write_fail/filter_fail。

## 12. 测试与验收
1. 单元测试：过滤器、路径清洗、时间戳/命名函数。  
2. 集成测试：真实窗口拉流 + 会话落盘 + 中断恢复。  
3. 验收标准：
   - 20 分钟会话不中断。  
   - `samples.jsonl` 与图片数量一致。  
   - 失败时 manifest 仍可读且统计完整。

# 训练数据资产管理工作台：架构总览

**版本**：v2.2  
**日期**：2026-02-26  
**角色**：架构与逻辑工程师（yangmq17）

## 1. 文档目标与范围
本文件定义“采集 -> 筛选 -> 预标注 -> 导出”的统一架构边界，作为 02~07 分册文档的总入口。  
本阶段目标是把工具从“时间线采样器”升级为“数据资产管理工作台”。

## 2. 核心原则
1. 状态驱动：以样本生命周期为中心，不以临时目录操作为中心。  
2. 可复现：每次导出可由 manifest 在新环境重建。  
3. 可追溯：关键状态变更必须记录 who/when/why。  
4. 可恢复：预标注与导出失败后可回滚，不污染正式结果目录。  
5. 渐进迁移：保留旧入口，新增 v2 流程灰度上线。

## 3. 分层架构
1. 表现层（UI Workbench）  
职责：流程导航、实时预览、筛选视图、任务控制、日志与告警。

2. 应用服务层（Use Case Services）  
职责：采集编排、筛选编排、预标注编排、导出编排、任务恢复。

3. 领域层（Domain）  
职责：样本状态机、筛选表达式、导出策略、数据集拆分策略、任务状态机。

4. 基础设施层（Infrastructure）  
职责：捕获后端（WGC/MSS）、文件存储、配置加载、模型推理、序列化与校验。

## 4. 样本生命周期状态机
```text
raw -> auto_filtered -> curated -> selected -> pseudo_labeled -> reviewed -> train_ready
```

状态说明：
1. `raw`：帧已落盘并写入样本记录。  
2. `auto_filtered`：自动质量过滤完成（模糊/重复/异常判定）。  
3. `curated`：人工标记完成（star/reject/review/none）。  
4. `selected`：满足导出候选条件。  
5. `pseudo_labeled`：已绑定伪标签版本。  
6. `reviewed`：人工复核通过或修订。  
7. `train_ready`：数据格式完整性校验通过。

幂等约束：
1. 同一 `sample_id + target_state` 重复执行不应产生重复副作用。  
2. 失败重试后不得生成重复文件或冲突记录。  
3. 所有状态跃迁写审计日志并带操作来源。

## 5. 模块边界
1. 采集模块只负责“拿到帧 + 质量过滤 + 元数据记录”，不做人工筛选逻辑。  
2. 筛选模块只负责“视图与标记”，不直接落地训练集。  
3. 预标注模块只负责“任务编排与预测产出”，不决定最终入训样本。  
4. 导出模块负责“拆分、格式化、校验、可复现清单”，是训练前最后关卡。

## 6. 统一契约（跨模块最小集合）
1. `samples.jsonl`：样本事实表。  
2. `session_manifest.json`：采集会话配置与环境快照。  
3. `pseudo_task_manifest.json`：预标注任务记录。  
4. `selection_manifest.json`：筛选/导出可复现清单。  
5. `validation_report.json`：导出结果质量与格式校验报告。

## 7. 非功能目标（SLO）
1. 可靠性：导出流程异常中断后可恢复或可回滚。  
2. 性能：1 万级样本浏览不出现明显卡顿（缩略图懒加载 + 后台线程）。  
3. 可观测性：关键操作具备日志、计数、耗时与错误分类。  
4. 可维护性：配置驱动阈值与策略，避免硬编码散落。

## 8. 版本与迁移策略
1. 分支策略：在 `docs/workbench-v2-refactor` 完成文档定稿后再推进代码重构。  
2. 迁移策略：旧流程保持可用，新增 v2 流程并行验证。  
3. 回滚策略：出现问题优先 `git revert` 指定提交，不使用 `reset --hard`。
